# 东京精选内容

`tokyo.json` 是应用实际读取的精选内容快照，独立于全库 `index.json` 和 `animeway.sqlite3`。它将东京地点、场景和短手册与已知上游记录映射到稳定地点身份。2026-09-30 扩展批次另见[审查记录](../../docs/pilot-expansion-20260930.md)。

东京坐标框内其他作品的离线候选清单在 `candidates/tokyo_bbox_works.json`，其定义、质量边界与扩展准入见[数据范围](../../docs/data-scope.md)。该清单不参与运行时规划，也不是已审核地点。

## 数据结构

| 集合 | 用途 |
|---|---|
| `anime` | 作品、版本、别名、场景与代表地点 |
| `locations` | 现实地点、坐标、片区、访问状态、入口／机位、上游身份和版本 |
| `scenes` | 作品与地点的场景关联、来源及素材使用范围；未知集数／时间码保留为空 |
| `routes` | 短手册模板、必去／可选站、停留建议、连接参考和发布状态 |
| `destinations` | 东京及片区层级，用于筛选和旅行组织 |
| `sources` | 来源链接、署名、使用说明与支持范围 |

当前有 8 部精选作品、91 个归并地点、103 个场景关联和 7 条短手册。其中新增 6 部作品、21 个地点、27 个场景关联和 4 条原型短手册。场景关联条数不等于已完成独立画面对照的条数。四谷站—须贺神社短线完成限定范围桌面资料核查；其余六条仍是原型，七条均未完成真实用户和现场验收。

## 修改原则

- 保持 `id` 稳定；多个场景可以对应同一地点，不能只按名称或邻近坐标盲目合并。
- 同时维护作品、地点、场景和来源的引用关系。撤下使用状态标志保留原身份，以便已保存行程明确提示失效。
- 地点事实与个人选择分开维护；更新资料不应覆盖用户的行程顺序、取舍或现场记录。
- `content_ready`、`field_verified`、`user_validated` 表示不同证据，运行测试或填写 JSON 不等于完成现场／用户验证。
- 未知访问规则、开放时间、集数和机位保留未知；官方接近说明、编辑建议和离线估算不能改标为实测交通。
- 精选场景的上游素材仅跳转原始来源，不嵌入或打包未知权利图片；来源存在不代表已取得再发布许可。用户上传照片由私人记录与分享授权机制另行管理。

应用通过 `core/pilot.py` 载入快照，通过维护者审核记录叠加变更；投稿不直接改写上游全库文件。审核命令、回撤和数据库备份见 [部署与维护](../../docs/operations.md)。

修改后应在隔离数据目录启动应用，核对作品、地点、场景、手册及个人 Trip 的引用与回退行为；不要用私人真实数据做检查。

`tokyo.json` 是运行快照；`candidates/` 是从现有索引派生的审查清单，不作为应用运行依赖。未核查的候选地点不得仅凭此清单加入 Trip。
