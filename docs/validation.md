# 验证状态

本页记录当前东京 Trip 流程的可复核证据和仍需现场验证的边界。自动化通过表示代码在测试输入下符合约定，不代表真实交通、地点或用户可用性已获验收。

## 已覆盖的行为

| 场景 | 自动化检查 |
|---|---|
| 步行估算与公共交通未知值 | 交通方式、时间和费用状态在草案、保存后与当天评估中一致；未知不补零，不悄悄改为驾车或步行 |
| 单段交通覆盖与计划变更 | 显式覆盖随保存、备份及重新打开保留；调整顺序和日期后重新评估；规划版本与现场事件分开 |
| 多入口创建 | 表单、AI 路书、手册、地图与背包进入同一草案编辑器；草案暂存后明确保存，继续使用同一 Trip ID |
| 当天使用 | 外部导航传递所选交通方式；到访需显式确认，跳过／临时关闭不算到访，剩余路段重评估 |
| 旧资料退出 | 旧副本可读、导出和从旧备份恢复，不能新建、编辑或启动旧当天模式；转换逐项列出遗漏与变化，原清单不被改写 |
| 导航和降级 | 三个顶层入口可用，地图关闭时仍有文字探索入口 |

代码检查命令与 CI 一致：

```bash
uv lock --check
uv sync --frozen --group dev
uv run ruff check .
uv run mypy
uv run python -m compileall -q app.py assets components core data_factory scripts utils tests
uv run python -m unittest discover -s tests -v
node --check assets/identity/identity.js
node --check assets/map/map.js
uv run python -m data_factory.release --root /tmp/animeway-public-snapshots --offline
```

截至 2026-09-29，本地自动化 **40 个用例通过**；锁文件检查、lint、配置范围内的类型检查、模块编译、浏览器脚本语法检查及离线公开快照构建通过。锁文件检查需要访问沙箱外的 uv 缓存，已在获准环境中执行。阶段开发过程的单独记录已合并到本页和[架构说明](architecture.md)。

## 数据核对

可在实际部署的私人库上先做一致备份，再执行只读汇总：

```bash
uv run python -m scripts.audit_legacy_trips --db /absolute/path/to/private.sqlite3
```

输出只有旧副本、站点可转换状态、当前事实变化、个人 Trip 和草案数量，不含身份、标题或地点名称。当前本地开发库的旧副本、个人 Trip 与草案均为 0，因此尚无真实历史数据的逐条转换证据。合成旧备份已覆盖重复、缺失、关闭、资料变化、只读兼容与转换结果一致性；部署时仍需对真实旧记录抽样复核。

## 发布前仍需取得的证据

1. **真实用户任务。** 请未参与开发的使用者分别用桌面和手机完成“选作品与时间 → 解释草案交通状态 → 修改一段交通 → 保存并重新打开 → 当天跳过或确认到访”。观察者只给任务，不解释术语；记录是否独立完成、耗时、误解、求助和复现步骤。
2. **东京现场路线。** 至少覆盖短途步行、跨片区公共交通、地点关闭或不可进入、已离开上一个站点四种情况。记录计划与实际交通、等候／换乘、时间、费用、访问状态及外部导航差异；不得把外部地图结果直接记为应用已核验事实。
3. **实际设备。** 在 iOS 与 Android 检查地图／文字列表、表单输入、键盘遮挡、按钮可触达、外部地图往返后状态，以及记录、备份恢复和分享撤下。
4. **素材和公开数据权利。** 复核实际发布范围内的图片、来源与署名。代码 MIT 许可证不自动覆盖上游点位、封面、场景图或地图服务。

通过条件是：使用者能独立解释“估算”和“待核查”，指出未知费用与不能确定的结束时间，完成至少一次明确的路线调整；现场没有误导性的确定时刻或费用展示。失败项需修复并复测。上述证据未取得前，项目不标记为 `release_ready`。当前尚未持久化保存时交通评估快照，也不读取现场当前位置；这两项需在后续产品决策中明确范围。
