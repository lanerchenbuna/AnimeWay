# AnimeWay 数据范围与扩展准入

本文件规定「可发现」和「可规划」分别意味着什么，并给出东京扩展的候选池。它基于仓库内 `knowledge_base/animeway.sqlite3`、`knowledge_base/raw/crawl_state.json` 和 `knowledge_base/pilot/tokyo.json` 的一次离线盘点。候选池不是经过审核的旅行地点；运行中的 Trip 范围仍以东京精选为准。

复算命令：

```bash
python -m scripts.audit_data_scope --write-inventory
```

逐部作品的完整清单位于 [`knowledge_base/pilot/candidates/tokyo_bbox_works.json`](../knowledge_base/pilot/candidates/tokyo_bbox_works.json)。清单含索引 SHA-256、范围定义、每部作品的坐标框内记录数与审查状态。它是离线审查材料，不被应用读取，也不自动改变 Trip 资格。

审查一部作品的逐点记录，例如：

```bash
python -m scripts.audit_data_scope --work-id 296659
```

逐点输出含原始名称、坐标、来源城市标签和已映射的精选地点 ID；空的来源链接和核验日期会保持空值。

## 当前真实覆盖

| 层级 | 粒度 | 当前数量 | 能向用户承诺什么 |
|---|---|---:|---|
| 作品元数据 | 作品 | 7,966 | 可以检索作品资料；其中许多没有点位 |
| 全库点位索引 | 作品 / 来源点位记录 | 906 / 23,173 | 可以发现来源点位；不等于独立现实地点或可规划范围 |
| 东京坐标框候选 | 作品 / 来源点位记录 | 485 / 7,739 | 只说明坐标落在初筛框内；含东京外缘和相邻地区 |
| 至少 10 条框内记录的作品 | 作品 / 来源点位记录 | 211 / 6,811 | 适合优先人工盘点的规模线索；不是质量线索 |
| 东京精选 | 作品 / 归并地点 / 场景关联 / 手册 | 8 / 91 / 103 / 7 | 当前应用的可规划内容范围；其中四条新手册仍是原型，不代表现场已验收 |

初筛框为经度 `139.3–139.95`、纬度 `35.4–35.9`，与现有 Trip 自定义起终点的限制一致。它**不是东京都行政边界**。框内 7,739 条记录只占全库点位的约 33.4%；91 个精选地点与 7,739 条来源记录的粒度不同，不能直接相减为「缺少多少个地点」。现有精选的 103 条上游映射能在框内索引逐项找到。清单中的 `partially_curated` 仅表示该作品已有精选内容，不能推断它在框内的所有记录都经过审查。

## 会影响扩展的质量事实

1. 框内索引的 `source_url` 和 `verified_at` 均为 7,739/7,739 空值。地图索引会构造作品页来源链接，但这不是每个点位已独立核验的证据。精选内容另存有来源及桌面核查信息，不应以索引空值否定已有精选工作。
2. 框内 7,739 条记录只形成 7,062 个按经纬度四位小数取整的坐标格，其中 494 个格有多条记录。共享坐标既可能表示同一地点的多个场景，也可能是不同入口、楼层或误标；不能用坐标自动合并。
3. 来源的 `city` 不能当作逐点行政区。例如 `GIRLS BAND CRY` 的 170 条框内记录全部标为「川崎市」，但样本名称包含东京站；相反，框内也有邻近东京但实际不在东京都的地点。最终行政归属需逐点查证。
4. 全库 7,966 部作品中只有 906 部有已索引点位。把作品检索数量表述成路线可规划数量会误导使用者。
5. 当前东京精选地点的访问状态为 `unknown` 86 个、`restricted` 5 个；地理状态为 `coordinate_screened` 35 个、`desk_reviewed` 54 个、`official_reference` 2 个。它们也不是 91 个经过现场验证的地点。当前代码允许这些地点进入 Trip，并在评估中提示未知和限制。
6. 运行索引标记为 `2026-07-24T12:43:24` 生成，审查清单是这份仓库快照的盘点，不代表 2026 年 9 月 30 日上游现况。每批正式扩展前应按现有刷新、审核、发布流程重新取得并比对来源变化。

以上统计由 [`scripts/audit_data_scope.py`](../scripts/audit_data_scope.py) 读取本地快照生成。索引或精选变更后应重跑盘点；清单中的 SHA-256 用于确认数字对应的索引版本。

## 建议采用的范围层级

| 状态 | 必要条件 | 产品行为 |
|---|---|---|
| `metadata_only` | 有作品元数据，没有有效点位 | 可检索作品；明确显示暂无可用地点 |
| `discovery_only` | 有来源点位与有效坐标，保留来源作品和点位 ID | 可浏览地图或列表，显示「来源点位，尚未核验」；不进入 Trip 候选 |
| `geography_candidate` | 初筛框命中，等待逐点确认行政归属、名称和物理位置 | 仅维护者审查；不能因坐标命中而自动推荐 |
| `editorial_trip` | 明确映射现实地点；来源、地点归属、访问边界已做桌面审查；重复场景已归并；无已知禁止访问或撤下 | 可手动加入 Trip；未知时刻、费用和机位继续显示未知 |
| `recommended_route` | 在上一层基础上，逐站理由、起终点、连接范围、冲突与删除站后的处理均完成审核 | 可作为路线草案推荐；标记桌面或现场验收状态 |
| `field_validated` | 有真实设备、现场路线和用户任务验收记录 | 才能宣称通过现场使用验证；仍需核对数据是否过期 |

这是一份**拟实施的数据契约**，不是现有程序中已全部实现的状态枚举。现有程序实际以东京精选 `locations` 和 `trip_eligible()` 判定能否进入 Trip；其中 `basic` 记录也可能被使用。扩展时应先建立逐点审查记录，再修改准入规则，避免仅把全库地图点位放入精选文件就使它们自动可规划。

第二轮可盘点《秒速5厘米》（927，103 条）、《言叶之庭》（58949，73 条）、《四月是你的谎言》（100444，60 条）。`GIRLS BAND CRY`（431767，170 条）和《更衣人偶坠入爱河》（333158，61 条）虽有较多框内记录，来源城市标签与东京坐标框的关系尤其需要逐点厘清，应先做行政归属审查。其余候选可从完整清单按数量、片区和用户需求继续排序；数量不应单独决定发布顺序。

建议首轮每部作品先选一个**同片区、公共区域可观察**的小组，而不是收录全部点位。每组选点应有一个车站或明确起点、数个可删的场景地点、返回或结束说明。具体数量在人工去重和实地可达性检查后确定，不以固定配额凑数。

## 每个新增地点必须留下的审查字段

| 字段组 | 最低记录 |
|---|---|
| 身份 | 稳定 `location_id`；一对多的来源作品 ID / 点位 ID；明确归并或拆分理由；旧 ID 迁移关系 |
| 地理 | 坐标、物理地点名称、行政归属、片区、坐标代表的是建筑／入口／机位哪一种，以及核查来源和日期 |
| 作品关联 | 作品版本、场景关联来源、独立比对状态；集数或时间码未知时保留空值 |
| 访问 | 公共外观／限制／关闭／禁止／未知、入口和机位、官方规则链接、核查日期、临时变化风险 |
| 素材 | 每张图的 `origin` 和 `originURL`（如可获得）、署名、展示／下载／分享权限；无依据时只留来源链接 |
| 规划 | 建议停留只是编辑建议；连接时间标记估算或来源限定参考；公共交通时长与费用继续保持未知，直到有已验收提供方 |
| 生命周期 | 上游更新时间、内部复核时间、来源版本、撤下标记和变更说明；已保存 Trip 保留历史选择并提示变化 |

## 接入顺序与完成标准

1. 从完整候选清单选一部作品，逐点建立审查表；排除东京框外、非东京都、私宅／禁止访问、无可追溯来源和明显重复的记录。坐标仅作初筛。
2. 把保留的来源记录归并成现实地点，并将场景、作品和来源逐项连到稳定 ID。修改 `tokyo.json` 前验证所有引用、坐标和状态；未知事实不得补造。
3. 新地点先作为可手动选择的草案范围；只有路线内容和连接边界也完成审核，才进入自动推荐。扩大作品列表时，同时更新界面的范围说明与空结果提示。
4. 对每部新增作品测试「搜索 → 选点 → 草案 → 编辑 → 保存 → 重新打开 → 地点撤下后的重评估」。对跨作品共址、来源 ID 变化、过期访问状态和备份恢复做回归检查。
5. 逐部记录：候选来源点位数、行政审查数、归并后地点数、可手动规划数、可推荐路线数、剩余阻断原因。只有这些数可复算，才公开宣称新增了多少可规划作品和地点。

当前只将八部作品的 91 个精选地点开放为 Trip 内容，**没有把 485 部作品或 7,739 条候选点位整体开放**。公开数据条款、图片权利、交通事实和现场验证仍按 [`知识库原始数据说明`](../knowledge_base/raw/README.md)及[`验证状态`](validation.md)处理。
